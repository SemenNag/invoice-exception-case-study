# Открытый датасет core-v1

10 изолированных кейсов, 12 PDF (10 входных и 2 оригинала для сравнения), 12 шагов. Все компании, контакты и банковские реквизиты вымышлены. Даты и ставки налога — фиксированные параметры задания.

Каждая папка — один счёт со своим контекстом и ожидаемыми результатами:

```text
dataset/cases/case-001/
├── case.json
├── documents/
│   └── document-001.pdf
├── context/
│   ├── purchase-orders.json
│   ├── goods-receipts.json
│   ├── suppliers.json
│   ├── buyers.json
│   └── invoice-history.json
├── steps/
│   └── step-001.json
└── expected/
    ├── extraction.json
    ├── step-001.json
    └── notes.md
```

| Файл / папка | Назначение |
|---|---|
| `case.json` | Оглавление сценария: входные документы, их хеши и последовательность шагов |
| `documents/` | PDF, который читает агент |
| `context/` | Данные для сверки: заказы, приёмки, поставщики, покупатели и ранее учтённые счета |
| `steps/` | Готовые JSON-запросы, которые eval-runner последовательно передаёт приложению кандидата |
| `expected/extraction.json` | Правильное извлечение фактов из PDF, включая ссылки на страницы и фрагменты текста |
| `expected/step-NNN.json` | Ожидаемый ответ приложения после соответствующего шага |
| `expected/notes.md` | Объяснение сценария: расчёты и намеренное расхождение |

Есть **два способа использовать один кейс**:

- **Через агента:** агент получает PDF и контекст, извлекает факты и работает через MCP. Эталоны ему не передаются.
- **Через evals:** runner берёт готовый запрос из `steps/`, передаёт адаптеру и сравнивает ответ с `expected/step-NNN.json`. Чтение PDF здесь не проверяется.

В большинстве кейсов один шаг. В `case-010` их три:

```text
step-001: регистрация фактов       → needs_information
step-002: предложение агента       → needs_review
step-003: подтверждение человека   → clear
```

Каждый шаг запускается отдельным процессом, но использует общее состояние своего кейса. Между разными кейсами состояние изолировано.

В `case-008` и `case-009` дополнительно лежат `original-001.pdf` и `original-extraction.json` — оригинал ранее учтённого счёта для проверки дубликата или конфликта.

Команды запуска и объяснение evals — в [README проекта](../README.md), контракт — в [EVALUATION](../docs/EVALUATION.md).
